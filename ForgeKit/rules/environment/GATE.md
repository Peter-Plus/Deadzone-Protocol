# 动态通行设施 · gate

先读 [公共规范](../ENVIRONMENT_RULES.md) 和 [nodes.v1](../NODE_ANIMATIONS.md)。首版支持一扇沿本地 X 轴平移的铁门，以及右侧门禁开关；不包含箱子、附魔台等已完成设施。

2026-10-06 内容范围扩展至军事、研究室内的一次性侧滑门，所有门只能开启一次、不能关闭；保护区仍使用两扇大铁门。关闭门阻挡角色及子弹。室内门作为独立 gate 资产安装，不烘焙为建筑静态墙；多门组合与室内两侧交互参考的表达按实际制作需要补充，当前工具不因此自动具备游戏组装能力。制作人明确暂不安排新增前置验证，后续制作或接入遇到问题再修。关闭时敌人被挡住并停在门前可接受；开启后导航应更新，不能永久保留关闭阻挡。

- 门框、侧墙、开关、门扇分节点。门扇为根级 Box Part，角色不能把整座门框当作活动物体。
- `gate.leaf / switchNode / duration / travel / passage / onlyOpen` 明确活动节点、交互 Socket、时长、位移、通道尺寸和只开不关规则。
- 模型和动画仍由现有 model.v1 / nodes.v1 编译，动画只有两个线性位置关键帧，与 gate 的时长和位移严格匹配。独立 `.anim.glb`，末帧保持开启；不能把门动画绑定为人形动画。
- 碰撞位置按相同开启进度变化，禁止交互瞬间就直接删除碰撞。不同体型的通行条件通过实际净空查询，不用固定“播完一半即可通过”。预览显示所选量规整条路径是否可通。
- 预留范围必须覆盖完整滑动行程，门收纳侧禁止布置角色出生点或其他阻碍。动画采样条和重置按钮只用于验收，不代表游戏可以关门。
- 玩法维护已开启状态，保存/恢复后直接设置动画姿态及碰撞状态，不必重播。首次开任一门永久纳入保护区敌人迁移范围是游戏逻辑，资产不能自动决定。

样件通道位于原点，右侧含开关与收纳侧墙；门扇移动 6.5m，时长 3 秒。时长和造型均为参考，可在正式定义中调整；工具会重新校验关键帧和碰撞。

已验证独立实例、动画/碰撞全程位置一致、关闭阻挡、开启可通过、实际开启过程中单体通过。未实现正式导航图重建、多人避让或整圈特别保护区生成。其他开门形式（旋转双开、卷帘、升降）须先扩展规范和物理检查，不能只改动画而保留平移碰撞公式。

2026-10-06 室内门组合补充：building.doors 可引用独立 gate（id/asset/position/yaw/pocket），position 为建筑局部米制，yaw 为度。构建时将同级 doors 源依赖加入当前输出批次，门的规范登记保持独立；不把活动门烘焙为固定墙。组合预览中每实例独立状态，一次开启并保持末帧，移动碰撞随动画同进度变换；绿色开关可点击，重置和采样只作验收。组合通路检查使用所有门完全开启状态，关闭阻挡及中间帧另外检查。此能力属于 ForgeKit，不表示游戏运行时已接入。

2026-10-06 保护区围墙组合补充：environment-preview-assembly.v1 参考可用 instances 引用静态 barrier，并以 doors（id/asset/position/yaw/pocket）、exclusions 和 routes 引用独立 gate。构建器从同级 barriers/doors 正式源解析依赖，预览复用独立门实例、动画与碰撞同步逻辑；检查重复实例、依赖缺失、收纳区和全开路线。此参考格式不扩展正式 environment.v1 的 barrier 字段，也不是游戏区域生成配置。保护区门型号 FSA_ENV_Door_ProtectedSlide，外侧右墙单开关、内侧侧滑、3秒 Open、净通道5.60×3.85m；完整装配入口在 doors 的 FSA_REF_Protected_TwoGates.assembly.json。
