# 程序化资产管线策划案

> 本文档是一份可直接交给 Codex 实施的工程规格。
>
> 目标：在一个空白目录中实现一套独立的程序化 3D 资产工具链。该工具链能够通过严格规则和结构化描述稳定生成模型资产与动画资产，并提供独立预览器进行检查。
>
> 本工具链完全独立，不依赖任何具体业务 Runtime。

---

# 1. 核心目标

整个系统必须满足以下目标：

1. Codex 可以阅读规则文档，根据规则稳定生成资产描述文件。
2. 模型源文件必须是可读、可编辑、可验证的结构化文本。
3. 动画源文件必须是可读、可编辑、可验证的结构化文本。
4. 模型最终产物优先为单文件 `.glb`。
5. 动画最终产物优先为单文件 `.anim.glb`。
6. 所有人形角色使用统一 Humanoid Rig，使动画能够复用。
7. 工具链必须包含严格 Validator，禁止非法数据进入编译阶段。
8. 编译器负责将结构化定义转换成最终 GLB。
9. 预览器可以浏览指定资产目录中的模型和动画。
10. 预览器一次只能显示一个模型、播放一个动画。
11. 动画不兼容时不得播放，并明确显示原因。
12. 预览器支持 WASD 移动、鼠标旋转视角。
13. 工具链支持 Watch / Hot Reload。
14. 不允许 Codex 直接生成二进制 GLB。
15. 不允许 Codex 直接手写大量顶点、索引、Quaternion。
16. 所有核心格式必须具有 JSON Schema。
17. 所有输出必须可复现：相同输入应生成相同结果。


# 5. 源资产与最终资产

必须明确区分：

```text
Source Asset
```

和：

```text
Compiled Asset
```

源模型：

```text
*.model.json
```

源动画：

```text
*.anim.json
```

源姿势：

```text
*.pose.json
```

最终模型：

```text
*.glb
```

最终动画：

```text
*.anim.glb
```

禁止直接修改 `assets/generated/` 中的文件。

生成目录中的内容始终视为 Compiler Output。

# 6. 坐标系统

必须统一坐标规范。

采用 Three.js 常用约定：

```text
+Y = Up
+X = Right
+Z = Forward
```

单位：

```text
1 Unit = 1 Meter
```

所有 Definition 中：

```text
Position = Meter
Rotation = Euler Degrees
Scale = scalar/vector
```

Codex 不得直接写 Quaternion。

Compiler 内部负责：

```text
Euler Degrees
→ Radians
→ Quaternion
```

---

# 7. Pivot / Origin 规则

不同模型必须拥有确定的 Pivot。

## 7.1 Humanoid

```text
Origin = 双脚中心对应的地面点
```

角色站立时：

```text
Y = 0
```

为地面。

## 7.2 Building

```text
Origin = 建筑底面中心
```

## 7.3 Weapon

```text
Origin = Weapon Root / Primary Grip Reference
```

Weapon DSL 必须允许定义额外 Socket。


# 9. Model DSL V1

Model Definition 是 Codex 生成模型的主要接口。

基础格式：

```json
{
  "schema": "model.v1",
  "id": "example.model",
  "type": "static",
  "units": "meter",
  "root": {
    "position": [0, 0, 0],
    "rotation": [0, 0, 0],
    "scale": [1, 1, 1]
  },
  "parts": []
}
```

# 10. Primitive 支持

V1 至少支持：

```text
box
sphere
cylinder
capsule
cone
plane
```

每个 Primitive 必须由参数生成。

禁止：

```text
手工填写大量 vertices
手工填写大量 indices
```

示例：

```json
{
  "id": "receiver",
  "shape": "box",
  "size": [0.12, 0.18, 0.48],
  "position": [0, 1.1, 0],
  "rotation": [0, 0, 0],
  "material": "metal.dark"
}
```

Cylinder 示例：

```json
{
  "id": "barrel",
  "shape": "cylinder",
  "radius": 0.025,
  "length": 0.45,
  "axis": "z",
  "position": [0, 1.12, 0.44],
  "material": "metal.dark"
}
```

---

# 11. Part 层级

Model DSL 必须支持 Parent / Child。

例如：

```json
{
  "id": "scope",
  "parent": "receiver",
  "shape": "box",
  "size": [0.05, 0.05, 0.12],
  "position": [0, 0.08, 0.05]
}
```

position / rotation / scale 默认解释为：

```text
Local Transform
```

相对于 parent。

如果无 parent：

```text
parent = model root
```

---

# 12. Material DSL

第一版只要求低复杂度 PBR Material。

至少支持：

```text
color
roughness
metalness
emissive
opacity
transparent
```

例如：

```json
{
  "schema": "material.v1",
  "id": "metal.dark",
  "color": "#292929",
  "roughness": 0.58,
  "metalness": 0.72
}
```

纹理不是 V1 必需项。

优先通过：

```text
几何
颜色
材质参数
```

建立统一 Stylized / Low Poly 风格。

---

# 13. Socket

Model DSL 应支持：

```text
Socket
```

Socket 本质为命名 Transform。

示例：

```json
{
  "sockets": [
    {
      "id": "muzzle",
      "parent": "barrel",
      "position": [0, 0, 0.225],
      "rotation": [0, 0, 0]
    }
  ]
}
```

Socket 应随模型写入 GLB Metadata 或 Node。

---

# 14. Humanoid Model

所有人形模型必须：

```text
rig = humanoid.v1
```

Humanoid 模型应复用统一 Skeleton。

V1 推荐采用：

> Rigid Articulated Humanoid

即：

- 每个身体部件是简单 Primitive Mesh。
- Mesh 直接挂在对应 Bone 下。
- 第一版不要求连续 Skin Weight 蒙皮。
- 动画驱动 Bone，Mesh 随 Bone 运动。

优点：

- 极易程序化生成。
- 极易调试。
- 不需要复杂 Skinning。
- 所有动画天然复用。
- 非常适合 Codex。
- 可形成稳定 Low Poly 美术风格。

后续 V2 可以增加真正 SkinnedMesh，但不得破坏 `humanoid.v1` Bone Contract。

---

# 15. Canonical Humanoid Rig V1

统一骨架：

```text
Root
└── Hips
    ├── Spine
    │   └── Chest
    │       ├── Neck
    │       │   └── Head
    │       │
    │       ├── Clavicle_L
    │       │   └── UpperArm_L
    │       │       └── LowerArm_L
    │       │           └── Hand_L
    │       │
    │       └── Clavicle_R
    │           └── UpperArm_R
    │               └── LowerArm_R
    │                   └── Hand_R
    │
    ├── UpperLeg_L
    │   └── LowerLeg_L
    │       └── Foot_L
    │           └── Toe_L
    │
    └── UpperLeg_R
        └── LowerLeg_R
            └── Foot_R
                └── Toe_R
```

骨骼名称、层级关系、默认局部轴必须严格固定。

---

# 16. Humanoid 参数化结构

不同 Humanoid 允许不同：

```text
height
shoulderWidth
hipWidth
armLength
legLength
headScale
handScale
footScale
bodyThickness
```

但不得改变：

```text
Bone Name
Bone Hierarchy
Rig Local Axis Convention
```

例如：

```json
{
  "schema": "model.v1",
  "id": "humanoid.example",
  "type": "humanoid",
  "rig": "humanoid.v1",
  "body": {
    "height": 1.8,
    "shoulderWidth": 0.48,
    "hipWidth": 0.32,
    "armLengthScale": 1.0,
    "legLengthScale": 1.0,
    "headScale": 1.0
  }
}
```

Compiler 根据参数自动创建 Skeleton 和身体部件。

---

# 17. Humanoid 默认姿势

统一 Reference Pose：

```text
T-Pose
```

要求：

- 双脚朝 +Z。
- 双腿竖直。
- 双臂沿 ±X 展开。
- 头部朝 +Z。
- Root 位于地面。
- Hips 位于骨盆中心。

所有动画都以该参考 Rig 为基础。

---

# 18. Rig Metadata

所有 Humanoid GLB 必须写入：

```text
rigId
rigVersion
rigSignature
```

例如：

```json
{
  "rigId": "humanoid",
  "rigVersion": "1",
  "rigSignature": "..."
}
```

Rig Signature 由以下内容确定：

```text
Bone Name
Parent Bone
Canonical Axis
```

进行稳定 Hash。

不得把身高、骨长纳入 Signature。

不同体型仍必须共享同一个 Signature。

---

# 19. Animation DSL V1

动画源文件：

```text
*.anim.json
```

基础结构：

```json
{
  "schema": "animation.v1",
  "id": "animation.humanoid.walk",
  "rig": "humanoid.v1",
  "duration": 1.0,
  "loop": true,
  "mode": "timeline"
}
```

V1 支持两种模式：

```text
timeline
generator
```

---

# 20. Animation Timeline Mode

用于特殊动作。

例如：

```json
{
  "schema": "animation.v1",
  "id": "animation.humanoid.attack",
  "rig": "humanoid.v1",
  "duration": 0.8,
  "loop": false,
  "mode": "timeline",
  "tracks": {
    "UpperArm_R": [
      {
        "time": 0.0,
        "rotation": [0, 0, 0]
      },
      {
        "time": 0.3,
        "rotation": [-60, 15, 10]
      },
      {
        "time": 0.8,
        "rotation": [0, 0, 0]
      }
    ]
  }
}
```

Rotation 为：

```text
Euler Degrees
```

Compiler 转换为 QuaternionKeyframeTrack。

---

# 21. Pose

复杂动画建议支持 Pose 复用。

Pose 文件：

```text
*.pose.json
```

例如：

```json
{
  "schema": "pose.v1",
  "id": "pose.humanoid.left_step",
  "rig": "humanoid.v1",
  "bones": {
    "UpperLeg_L": {
      "rotation": [30, 0, 0]
    },
    "LowerLeg_L": {
      "rotation": [-25, 0, 0]
    },
    "UpperLeg_R": {
      "rotation": [-20, 0, 0]
    }
  }
}
```

Animation 可以：

```json
{
  "timeline": [
    {
      "time": 0.0,
      "pose": "pose.humanoid.left_step"
    },
    {
      "time": 0.5,
      "pose": "pose.humanoid.right_step"
    },
    {
      "time": 1.0,
      "pose": "pose.humanoid.left_step"
    }
  ]
}
```

---

# 22. Animation Generator Mode

常见循环动作优先使用参数化 Generator。

例如：

```json
{
  "schema": "animation.v1",
  "id": "animation.humanoid.walk",
  "rig": "humanoid.v1",
  "duration": 1.0,
  "loop": true,
  "mode": "generator",
  "generator": "humanoid.walk",
  "parameters": {
    "strideAngle": 32,
    "kneeBend": 24,
    "armSwing": 20,
    "bodyBob": 0.025,
    "hipTwist": 4
  }
}
```

V1 至少提供：

```text
humanoid.idle
humanoid.breathing
humanoid.walk
humanoid.run
```

Generator 负责生成稳定 Timeline。

Codex 优先通过修改参数控制常规动画。

---

# 23. Root Motion

V1 禁止 Root Motion。

所有动画：

```text
In Place
```

Root / Hips 不允许产生持续世界位移。

允许：

```text
上下轻微 Bob
局部旋转
短暂局部偏移
```

禁止 Walk/Run 使 Root 从 A 移动到 B。

Root Motion 预留 V2。

---

# 24. Animation Output

编译后的动画文件：

```text
walk.anim.glb
```

应包含：

```text
Canonical Skeleton
AnimationClip
Metadata
```

不包含角色 Mesh。

Metadata：

```text
animationId
rigId
rigVersion
rigSignature
duration
loop
```

Previewer 从该 GLB 获取 AnimationClip 后绑定到当前兼容模型。

---

# 25. Rig Compatibility

动画播放前必须检查：

```text
Model.rigId == Animation.rigId

Model.rigVersion == Animation.rigVersion

Model.rigSignature == Animation.rigSignature
```

任一不匹配：

```text
禁止播放
```

UI 显示：

```text
Animation incompatible with current model.
```

并显示具体 mismatch。

---

# 26. Validator

Validator 必须在 Compiler 前执行。

任何 Error：

```text
停止编译
```

Warning：

```text
允许编译
但打印警告
```

---

# 27. Model Validator

至少检查：

```text
schema version
asset id
duplicate part id
unknown parent
cyclic hierarchy
unsupported primitive
invalid dimensions
negative radius
negative length
NaN
Infinity
invalid material
invalid socket parent
invalid humanoid parameter
unknown rig
```

尺寸安全范围可配置。

例如：

```text
任何单轴绝对尺寸 > 1000m
→ Warning
```

---

# 28. Animation Validator

至少检查：

```text
schema version
unknown rig
unknown bone
duplicate track
time < 0
time > duration
timeline not sorted
NaN
Infinity
invalid Euler
duration <= 0
empty animation
```

Loop Animation 额外检查：

```text
首尾 Pose 差距过大
→ Warning
```

---

# 29. Error 输出规范

错误必须为 Codex 友好格式。

示例：

```text
ERROR [ANIM_UNKNOWN_BONE]
File: assets/definitions/animations/humanoid_walk.anim.json
Path: tracks.LeftUpperArm

Unknown bone "LeftUpperArm".

Expected canonical name:
UpperArm_L
```

要求：

- Error Code
- File
- JSON Path
- 问题描述
- 修复提示

不得只打印：

```text
Invalid animation
```

# 30. Asset Compiler

Compiler 顶层接口：

```text
AssetCompiler
```

内部：

```text
ModelCompiler
AnimationCompiler
MaterialCompiler
HumanoidCompiler
GltfWriter
```

编译流程：

```text
Read Definition
↓
JSON Schema Validation
↓
Semantic Validation
↓
Resolve References
↓
Compile Three.js Scene
↓
Attach Metadata
↓
GLTFExporter
↓
Write GLB
```

---

# 31. Determinism

相同 Definition 必须尽可能生成相同结果。

如果 Generator 使用随机：

```text
Definition 必须明确提供 seed
```

禁止隐式：

```text
Math.random()
```

生成资产。

# 35. Watch

```bash
npm run asset -- watch
```

监控：

```text
assets/definitions/**
rules/**
schemas/**
```

主要监听 Definition。

Definition 修改后：

```text
Validate Changed File
↓
Build Changed File
↓
Notify Previewer
```

Validation 失败：

```text
保留上一次正确生成结果
输出错误
```

不得用错误数据覆盖正常 GLB。

# 45. Hot Reload




```text

```

# 59. 设计底线

整个工具链必须遵循：

```text
Codex 生成描述
Compiler 生成资产
Previewer 检查结果
```

而不是：

```text
Codex 直接生成复杂二进制模型
```

Codex 需要操作的是：

```text
参数
部件
层级
姿势
动画参数
时间线
```

Compiler 负责：

```text
Geometry
Quaternion
AnimationClip
Skeleton
GLB
```

这是整套方案保证稳定性和可扩展性的核心。

# 60. 最终目标

完成 V1 后，使用者应该可以只向 Codex 提出类似需求：

```text
创建一个身高 1.9m、
手臂略长、
身体偏瘦、
头部稍大的基础人形模型。
```

Codex 根据规则创建：

```text
*.model.json
```

然后自动：

```text
validate
build
```

得到：

```text
*.glb
```

同理：

```text
创建一个较迟缓、步幅小、身体前倾的人形行走动画。
```

Codex 创建：

```text
*.anim.json
```

通过 Generator 参数或 Timeline 描述后生成：

```text
*.anim.glb
```

最终使用 Previewer 独立检查模型与动画结果。

该流程不得依赖传统 3D DCC 软件，必须完全通过代码、结构化定义和 Three.js 工具链完成。
