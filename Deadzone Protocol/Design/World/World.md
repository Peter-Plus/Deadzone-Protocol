# World

本文为正式单局的目标规则，不代表当前训练场实现。地区、背景与探索路线见 [WorldContent.md](WorldContent.md)，设施和交互物见 [WorldInteractions.md](WorldInteractions.md)，操作和迷雾地图见 [UI](../UI/UI.md)。2026-10-05 的 Test 验证仅证明部分空间能力可行，未自动接入正式游戏。

## 1. 世界结构

首版使用单张连续的正方形世界地图，场景基调为末世聚落与荒漠，包含单层室内探索、缓坡地形和实心环境障碍。六类地区及其邻近关系见 WorldContent。本地图包含三名唯一的区域首领和一名终极 Boss，首领区域独立随机分布，不强制绑定普通地区。

世界包含：

- 地形
- 建筑
- NPC
- 道具
- 武器
- 军备
- 敌人
- 空投
- 安全圈
- 世界事件

地图和资源生成主要由配置与 `WorldSeed` 决定。

## 3. Spawn Grid

Spawn Grid 只负责**世界初始化阶段的资源分布控制**。除各类资源自身的分布 Grid 外，还需要一个上层区域预留网格，先保证大型区域的合法占地与间距，再在剩余空间内投放内容。它不承担运行时空间查询。

不同资源允许使用不同分布 Grid：

```text
EnemySpawnGrid
WeaponSpawnGrid
ItemSpawnGrid
NPCSpawnGrid
```

上层预留网格按配置划分 Bucket，标记哪些格可放置大型区域、哪些已经被占用。`0` 表示可用、`1` 表示已被独占区域预留；这只是生成阶段的占用数据，不等同于地形碰撞、玩家不可通行或没有探索内容。

推荐生成顺序：

1. 随机选择合法的终极 Boss 区域并预留其圆形占地。
2. 放置 C1/C2/C3 各自唯一的圆形首领领地。
3. 放置玩家出生区域及初始商店 NPC。
4. 联合安排唯一特别保护区、周边军事基地与防疫站，再安排其他地区；依次满足数量、最大距离、最小间距及连通要求。允许有界回溯，不能因分步顺序丢失必需地区。
5. 地形平台与建筑布局联合生成，安排建筑、实心障碍、铁墙/门、入口坡道和 NPC；区域内部允许建筑与内容，但不能混淆上层区域预留与墙体碰撞。
6. 在合法区域放置装备、道具、大型神秘宝箱及两座普通附魔台，按地区与敌群包放置普通和精英敌人。物资不把上层区域格改为独占；敌人可在合法室内生成，需避开初始角色/物资占用及 NPC 小范围安全距离。生成顺序可调整，但最终必须完成交叉合法性检查。

每一步都先检查边界、占地、合法地形和与其他区域的最小间距，失败则在有界次数内重试；不能因为找不到位置而无限循环。若参数导致地图无法满足全部唯一区域，生成应报告配置错误或使用明确的降级方案，不默默丢失首领或 Boss。

首领同级最小间距、首领与 Boss 的上级最小间距、出生区与 Boss/首领的最小间距分别配置。建筑允许位于所属普通地区内部，但不能侵占其他独占场所；建筑间距、入口及坡道空间配置化，并检查实际占地，不要求同聚落等距排布。

普通与精英敌人以**敌群包**为生成单位：包可以稀疏或密集、覆盖一个格或更大的方形区域；先确定包区域，再为包内各敌人抽取经 SpawnRule 验证的具体位置。`EnemyGroupDensity` 在 0～1 之间，控制剩余可用区域中投放敌群包的比例；`1` 表示尝试覆盖全部符合条件的剩余区域，不代表每格塞入一个敌人或忽略出生安全距离与通行空间。密集大包可绑定高品质宝箱。总敌人数仍由关卡配置与合法位置共同限制。

每个资源 Bucket 的生成数量可采用：

```text
Count = BaseCount + RandomInteger(min(0, CountDelta), max(0, CountDelta))
```

数量抽样含两端；BaseCount 为非负整数，CountDelta 为带正负号的整数幅度。均匀整数抽样作为基础约定，不另隐含品质/权重规则。例如：

```text
BaseCount=10, CountDelta=5  → 10～15
BaseCount=8,  CountDelta=-3 → 5～8
CountDelta=0              → 固定数量
```

配置必须保证最小可能数量不小于零，否则报错；不静默截断负数。该口径适用于地区、建筑、NPC、资源及其他需要数量随机的配置。长度、高度、间距等连续量可按同样端点含义抽样，但须额外满足几何合法性。

物资可以同时有地区总量、建筑总量、类别/具体物品数量等约束。外层数量是内层分配的约束，不是额外再生成一批；先校验子项保底之和、可分配上限与父级数量可同时满足，再在合法预算内抽样分配。配置保底因空间不足不能实现时，按必需项重试/报错或按明确的可选项策略记录缺额，不能默默降低保底。UI 重开、页面重载显示或重复查询不能重抽已生成内容。

不同资源至少允许配置：

- GridSize
- BaseCount
- CountDelta（允许正负或零）
- MinSpacing
- SpawnRules
- 上层区域占用与间距约束
- 敌群包尺寸、密度及包内位置规则（敌人）

## 4. SpawnRule

任何资源生成都不能只依赖纯随机坐标。

生成位置统一经过 SpawnRule 合法性判断。

典型规则：

- 不超出地图边界。
- 不生成在禁止占用的建筑区域。
- 不与指定实体距离过近。
- 不生成在非法地形。
- 可以限制与玩家出生点的最小距离。
- 可以限制与其他资源的最小距离。
- 可以配置地区、建筑、室内子区域的类别限制、倾向和数量约束；NPC 指定地区时是硬限制，见 Character 的 NPC 规则。
- 唯一区域完整落在地图内且不与已预留区域重叠。
- 首领、Boss、出生区域满足各自的中心间距约束。
- 敌群与玩家出生点、交互物、必须通行的入口保持安全间距。
- 按实际体积检查地面支持、墙/屋顶、入口净空及可达性；地板、坡道和室外地形分别查询，不把屋顶误当室内放置面。
- 建筑实例变换同时应用于视觉、碰撞、导航、入口及资源区域；资源生成使用独立随机流，不因改变物品配置而扰动建筑/敌人初始布局。

具体规则可以按资源类型扩展。

## 5. Runtime SpatialGrid

运行时空间查询使用独立于 Spawn Grid 的二维空间哈希：

```text
SpatialGrid
```

用途包括：

- 查询玩家附近敌人。
- 查询附近 NPC。
- 查询附近掉落物。
- Enemy 激活候选查询。
- 降低全量实体遍历。
- 碰撞粗筛。
- AI 感知候选集。
- 空间交互查询。

SpatialGrid **不负责生成规则**。

### 5.1 基本结构

世界坐标根据 `CellSize` 映射到：

```text
Cell(x, y)
```

每个 Cell 维护其中的实体 ID 集合。

实体跨 Cell 移动时更新注册位置。

范围查询只扫描覆盖目标范围的 Cell。

具体 Hash 公式和数据结构由实现阶段决定。

## 6. Building

建筑由配置与模板驱动，区分可进入的单层建筑和不可进入的实心障碍。建筑占地允许不同长宽，不再统一用一个 Size 正方形兼任所有空间含义。

每个模板至少描述资产标识、局部原点、实际占地/预留范围、地坪标高、墙/屋顶/地板/坡道的简化碰撞、可通行入口、室内资源区域与禁放区域；每个实例描述唯一 ID、模板和位置/朝向。具体 Schema 由实现阶段确定。

区域预留防止生成重叠；实体墙体阻挡角色与射线；室内地板、入口和资源区域分别决定通行与投放。合法室内允许敌人、NPC 和物资，墙体内、屋顶及不可达区域禁止生成。不能将整栋可进入建筑包成实心碰撞盒或整块禁生区。

房屋保持直立，落在合适的水平建造平台上；地形与平台联合生成、平顺衔接。普通建筑取消外加坡板，入口优先齐平；需要门槛时采用 5～10cm 低地坪，最终摆放后的单次向上高差不超过 10cm，由玩家和敌人的自动跨步能力处理，不依赖跳跃或瞬移。导航须识别小台阶并区分上下行，角色控制器须支持跨步、贴地和正常走下边缘，群体仍需避让；这些是正式接入要求，不代表现有训练场已经实现。特殊高台必须另行设计地形衔接并验证，不能直接删坡道。实际门宽、净高和通道按需支持的角色体积验收，不能把 Test 的尺寸当正式固定数值，也不能为通过测试静默缩小模型。规范见 [ForgeKit 单层建筑](../../../ForgeKit/rules/environment/BUILDING.md)。

单层高度、占地、数量、间距和屋顶轮廓可在已验证范围内变化，变化后须同步碰撞、导航和采样范围。普通房屋首版不扩展动态门、多层、攀爬和破坏；特别保护区两扇铁门是明确的动态设施例外，规则见 WorldInteractions。

## 7. Bio Zone

生化安全圈采用状态机：

```text
Init
↓
Shrinking
↓
Stable
↓
Shrinking
↓
Stable
↓
...
↓
Converged
```

活动状态变化时通过屏幕提示告知玩家；地图页面持续提供当前活动状态文字。当前安全圈边界可见，探索迷雾不因此揭开；不由此额外承诺下一圈目标范围预告。具体展示见 [UI](../UI/UI.md)。只有 ESC 暂停菜单暂停圈阶段时钟，地图、商店等界面不暂停。

### 7.1 Init

负责：

- 初始化安全圈。
- 设置初始中心。
- 设置初始半径。
- 准备阶段数据。

### 7.2 Shrinking

安全圈在指定持续时间内从：

```text
CurrentRadius
→ TargetRadius
```

平滑变化。

必须基于 `DeltaTime`。

### 7.3 Stable

安全圈暂时停止缩小。

玩家可在该阶段：

- 搜索
- 战斗
- 调整装备
- 移动
- 与 NPC 交互

### 7.4 Converged（收束完成）

`Converged` 只表示生化圈达到最小目标半径并停止缩圈。SP 基础恢复在圈内外都结算，圈外另有持续 SP 损失；两者共同决定净变化，强力药品可能使圈外 SP 净增长。它不是 GameFlow 的 `Final`，不召唤终极 Boss，也不强迫玩家交互。

每局生化圈的最终目标区域落在终极 Boss 结界区域，终点中心与半径按该区域的合法范围配置，确保收束过程最终将玩家引向 Boss 战入口；即使圈已收束，玩家仍需主动交互才能开战。

区域首领战期间将生化圈阶段推进速度乘以 0.5，战斗结束后恢复；首领结界不取消圈外 SP 伤害。这是首领结界事件对圈进度的单向影响，安全圈阶段不作为区域首领或终极 Boss 的召唤条件。

## 8. DayNightSystem

游戏拥有完整昼夜循环。

当前基础周期：

```text
10 分钟 / 一个完整昼夜周期
```

DayNightSystem 负责：

- 时间推进
- 太阳方向
- 环境光变化
- 光照强度变化
- 色温变化
- 天空表现

昼夜系统与天气系统独立。

夜晚天空变暗但保持战斗与探索辨识度。昼/夜判定区间由配置决定，其他系统读取统一状态，不凭画面亮度猜测。影系角色与影系武器技能的夜晚冷却规则见 [Elements](../Combat/Elements.md)。首版不提供天气预告或天气干预功能。

---

## 9. WeatherSystem

基础天气：

```text
Sunny
Cloudy
Rain
```

WeatherSystem 与 GameFlowSystem 同级。

天气可影响：

- 环境光强度
- 光照色温
- 环境表现
- SP 恢复速度
- 特定武器效果
- 特定敌人能力

### 9.1 Rain

当前预期：

- 降低环境光。
- 调整色温。
- 播放雨水表现。
- 降低 SP 恢复速度。
- 全场角色火抗增加约 60 个百分点，约每 8 秒降低 2 层灼烧；可影响火附魔武器的实际效果。
- 毒阵生成时的持续时间和每秒附毒量提高；允许瘴疫兽在低生命时使用雨天技能。
- 房屋遮蔽雨水视觉，但不免除或改变上述 Gameplay 天气效果；雨天效果仍全场适用。

元素、状态与抗性结算见 `../Combat/Elements.md`；WeatherSystem 提供天气上下文与周期事件，不直接改写武器或敌人内部状态。

### 9.2 Sunny

当前预期：

- 环境整体更明亮。
- SP 恢复速度提高。

### 9.3 环境状态暴露

WeatherSystem 不直接修改具体 Weapon 或 Enemy 内部逻辑。

推荐通过：

```text
GameplayTag / EnvironmentTag
Modifier
Context
```

暴露环境状态。

例如：

```text
Environment.Raining
```

具体 Weapon 或 Enemy 根据环境状态自行处理自身规则。

## 10. WorldEventSystem

首版不增加额外随机世界事件。天气和昼夜是持续运行的环境系统，不计作随机世界事件；信号枪空投是玩家道具触发的设施生成。WorldEventSystem 仅保留未来扩展方向，当前不要求先实现空壳事件框架。

区域轰炸、尸潮增援、已击败首领复活、条件触发大规模迁移均只属制作人的后续想法，不是首版规则，也不改变目前首领唯一性和死亡奖励。

## 11. Airdrop

首版只保留信号枪空投，取消旧的固定节点空投目标。空投不吸引敌人，开箱前要求周围配置范围无存活敌人。位置、约 20～30 秒延迟、非法位置处理及内容领取统一见 [WorldInteractions](WorldInteractions.md#3-空投箱与信号枪)。

---

## 11.3 宝箱与附魔台

可装入背包的军备箱见 [Item](../Item/Item.md)；不可移动的大型神秘宝箱与空投箱见 [WorldInteractions](WorldInteractions.md)。箱内内容初始化时确定，重复打开 UI 不重抽。

地图仍初始化两座普通附魔台。炎巫、瘴疫兽中心各有一座受力量封锁的首领台，击败对应首领后解锁原台，不重复生成新台；每座一局只可附魔一次，均允许火或毒。设施状态见 WorldInteractions，消耗和效果见 Item 与 Elements。

## 12. GameFlow Final 阶段世界行为

玩家主动与最终区域交互物交互、召唤终极 Boss 后：

- 玩家附近敌人继续保持 Active。
- 具有迁移资格的远距离未清理敌人进入 Wandering。
- 敌人逐步向最终中心迁移。
- 靠近玩家后重新进入 Active。
- BossSystem 根据 GameFlowSystem 的交互请求生成终极 Boss，并在生成时吸收仍存活的区域首领。

特别保护区两门均从未开启时，区内敌人不具备最终迁移资格；任意一门首次开启后，区内存活敌人永久纳入迁移范围，门不可再关闭。过滤必须先于低精度移动，不能让 Wandering 的穿墙能力绕过这项规则。其他具备资格的存活敌人按原规则参与。

玩家前期清理的合格敌人越少，Final 阶段潜在残余敌人越多。战场附近运行完整 AI 的数量需要受遭遇容量控制；尚未进入的合格敌人不凭空消失，待容量允许再逐步加入。噩梦之石和场内尖刺规则见 WorldInteractions。

Boss 死亡后由 GameFlowSystem 进入 Victory。

具体 Enemy 和 Boss 行为见 [Character](../Character/Character.md) 与 [EnemyContent](../Character/EnemyContent.md)。
