# UI

## 1. 技术边界

UI 不使用 Three.js 作为主要实现。

主要采用：

```text
HTML
CSS
DOM
```

Three.js 负责 3D 世界表现。

UI 与 3D Render 保持职责分离。

---

## 2. 首版 UI 模块

至少包括：

```text
HUD
Inventory
Equipment
Shop
Map
Settings
Interaction
GameResult
```

具体页面拆分和视觉设计后续确定。

单局中只有 ESC 暂停菜单暂停游戏；背包、大地图、商店、军械师服务、附魔、物品详情及其他交互界面均不暂停。打开这些界面只改变输入焦点，不停止安全圈、敌人、状态恢复/损失或冷却。暂停与恢复的时间规则见 [Core](../Core/Core.md)。

---

## 3. Gameplay / UI 解耦

UI 不应直接深入读取或修改 Gameplay 对象内部状态。

推荐数据流：

```text
Gameplay
↓
ViewModel / UI Data
↓
UI
```

示例：

```text
AttributeChanged
↓
PlayerHUDViewModel
↓
HealthBar
```

目标是形成类似独立 UMG 层的职责边界：

- Gameplay 决定真实状态。
- ViewModel / UI Data 整理 UI 所需数据。
- DOM 负责最终显示和用户交互表现。

---

## 4. HUD

HUD 至少需要能够承载玩家实时 Gameplay 信息。

当前已明确的核心 Player 状态包括：

```text
HP
SP
Stamina
```

此外会逐步接入：

- Weapon / Ammo
- Interaction
- GameFlow / Zone 信息
- 毒伤、灼烧使用小方形图标，右下角数字表示层数；扇形阴影分别表示当前层毒素／每层容量（参考 100）、剩余时长／当前层最大时长。C3 战仍需提示接近引爆阈值
- 翻滚和暗影双刃的技能冷却使用同组小方形图标，扇形阴影表示剩余冷却／本次总冷却，不显示名称或秒数
- 当前选中的消耗品图标、右下角数量、Q 切换和 T 使用提示，以及共享消耗品槽冷却；消耗品槽位于武器槽右侧，不显示物品名称或数量前缀 x
- 区域首领与终极 Boss 血条；技能蓄力与范围预警由对应动画和场景表现承担，不要求 HUD 为每个技能增加专门提示

HP、SP、ST 以淡红、淡绿、淡黄属性条显示，不显示具体数值；图标与标签统一象牙白。武器槽使用简单卡片；属性条、消耗品和右侧武器简介使用无边框渐隐背景。视觉细则见 [UI 美术规范](../../Assets/ui/README.md)。

右上角为小地图；附近物品列表位于屏幕右侧，布局需避免相互遮挡。

## 5. Inventory / Equipment UI

Inventory 与 Equipment 在 Gameplay 上是两个独立系统，UI 也应明确区分：

```text
Inventory
→ 玩家持有的 Item

Equipment
→ 当前装备槽
```

更换 Equipment 时：

```text
打开 Inventory
↓
选择 Item
↓
替换 Equipment Slot
```

打开背包期间：

```text
游戏不暂停
```

UI 不能通过复制 Item 状态来维护独立 Equipment 数据。

装备 HUD 需要表达两个主武器槽、副武器、近战和投掷物，以及当前空手状态。按当前手持槽对应的快捷键会收枪；翻滚后也保持空手，直到玩家手动切出装备。具体槽位规则见 `../Item/Item.md`。

背包还需展示当前／最大容量、背包等级、备用弹药堆叠、头盔／护甲／靴子槽和消耗品选择。物品预览按类别展示品质、价值、容量、元素、便携及必要战斗属性；枪械显示适配弹药、当前弹匣弹量／容量和全自动／半自动／手动开火模式。已穿戴或放入武器槽的物品仍计入背包容量，不应在 UI 中看起来像已从背包移除。容量不足时，购买、拾取和开箱界面应说明原因并提供可理解的取舍。

## 6. Shop

Shop UI 用于 NPC 商店交互。

至少需要支持：

- 同一 Merchant 类型下配置的普通商人、军火商、神秘黑市商人等。
- 军械师的普通／高级拆解服务。
- 后续可扩展的特殊 NPC 交易。

商人 UI 显示配置名称与实际商品列表，固定商品和随机商品合并展示，不分成两套商店。是否显示出售功能取决于商人配置，默认开启；价值为 -1 的物品不可出售。商品在生成时确定，本局不因重开 UI 重抽或补货。出生商店使用固定货品，并明确提示离开出生区域或购买时间结束后不可再次购买。军械师界面必须展示普通拆解会销毁装备、高级拆解会返还未附魔装备与晶核，以及所需金币。具体价格和库存由配置确定。

附魔台交互界面展示剩余使用次数、可用晶核、目标装备、附魔后的元素与属性变化；每座附魔台一局只可使用一次。首领台未解锁时显示召唤首领与强制战斗提示，不显示可附魔假象。可携带军备箱在背包开启；大型神秘宝箱与空投箱在世界中开启后使用下文附近物品列表，不能要求玩家先把整个场景箱装进背包。

## 7. Map / Zone

右上角常驻小地图，M 打开/关闭大地图。两者消费同一份本局探索记录：开局全图遮蔽，只揭示出生点配置范围；随玩家移动揭开附近范围，已经探索的地区本局不再变暗。不因镜头远望、标点或系统已经知道全部生成数据就揭露未探索地点。

发现地区与设施后记录其位置和名称，例如军事基地、附魔台、商人和首领区域。首领与最终场所不在开局全图公开；玩家可以根据已探索区域关系与圈势推断它们。迷雾表示探索记录，不提供未观察敌人的实时雷达或动态位置。已发现设施的已知状态和本局位置可保留。

地图表达范围、玩家位置、当前安全圈、Converged 与 Final 的区别。圈边界属于生存信息，可叠加显示而不揭露底图和设施。安全圈活动状态变化时，屏幕显示提示，例如开始收缩、停止收缩/进入稳定阶段、收束完成；打开地图也能看到当前活动状态的文字说明。首版按这些状态提示表达圈势，不将本次确认扩展为提前显示下一圈目标范围或最终 Boss 位置。

玩家在大地图右键放置路线标点，单击已有标点取消；首版按一个活动手动标点组织，重新右键替换目标。允许标记未探索坐标，但不会因此揭开迷雾。关闭地图后显示带方向的路引 UI，路引限制在屏幕内的椭圆区域，目标在视野外时仍能看出应转向的方向；这是方位提示，不保证直线无障碍或自动规划路线。

首领、铁门与最终交互物在接近时显示明确操作及后果提示，不靠音效告知强制开战或保护区开门的迁移风险。

### 7.1 附近物品与设施操作

- 正式单局使用 E 作为统一拾取/交互键，覆盖地面物品、NPC、附魔台、铁门、首领/Boss 交互物及大型宝箱。F 不再是正式拾取键；当前训练场的既有射击备用键不在本轮文档修改中假装已被替换。
- 玩家靠近有效物品检测范围，屏幕右侧显示条目列表；同一时间只有一个选中条目，滚轮切换，E 领取选中条目。选中项消失后稳定转移焦点，不一次按键连拿多个物品。
- 单条展示图标、名称、数量与品质边框颜色。按住鼠标中键展示选中物品详细卡片，复用背包详情；松开、离开检测范围或目标失效时隐藏。查看详情不执行拾取。
- 二/三级背包等不可拾取道具也以同样条目和详情展示；E 取得后立即生效，不进入 Inventory。等级已满足等情况显示不可取得原因，不凭空消耗世界道具。
- 大型神秘宝箱/空投箱未开启时显示开箱提示与附近敌人的阻止原因；已开启且位于范围内时显示剩余内容条目，箱内物品没有独立地面模型。离开箱子只关闭列表，不清空奖励。
- 容量不足时保留物品并提示，不能静默丢弃。异变结晶仍是接触自动拾取的既定例外，不改成必须 E。
- 同时靠近物品与设施时必须明确显示当前 E 的唯一目标；滚轮用于附近列表选择时不同时切换武器，鼠标用于地图/商店时不同时转动视角或开火。具体焦点实现留给 UI，但不得产生一次输入多处生效。

## 8. GameResult

至少需要支持：

```text
Victory
Failure
```

混沌死亡由 GameFlowSystem 判定 Victory；玩家 HP 或 SP 清零进入 Failure。终局顺序和单局停止规则见 Core。

结算页面用雷达图展示五个维度，原始指标与显示归一化分开处理：

| 维度 | 统计方向 |
| --- | --- |
| 造成伤害 | 玩家本局造成的伤害。 |
| 承伤 | 玩家本局承受的伤害。 |
| 发育 | 累积直接获得的金币＋直接获取物品按价值折算的金币；排除出售收入和购买所得物品，避免交易重复计数。 |
| 准度 | 枪械命中率，仅计算枪械。 |
| 时长 | 通关时长；失败局可展示本次挑战持续时间。 |

发育统计对首次直接获取建立一致的来源口径，丢弃后重拾、开箱转移或物品形态变化不重复记收益；不可出售物品的价值 -1 不能直接作为负收益。具体折算、枪械命中率口径（含霰弹枪）、有效伤害统计、雷达图归一化及零分母处理由程序合理设计。

结算给出行动评级。制作人提供的方向为：

```text
S = F1(准度) + F2(时长)
  + (F3(造成伤害) - F4(承伤)) / F5(发育)
  + F6(发育)
```

这里 S 为综合评分的示意变量，F1～F6 的公式、权重及评级档位由程序设计和试玩调整，不照抄为未经处理的最终公式。高伤害或高发育不能自动等于高评价，应公平体现高难度、快速通关和较少资源投入的表现。

按本局数据颁发徽章／称号，例如高承伤的“不死鸟”、快速完成的“不速之客”，更快记录可有更高阶称号；具体条件、阈值、命名和展示由程序设计。另展示玩家击败的 C 级区域首领与 D 级终极 Boss 数量；混沌吞噬首领不计为玩家击败。

页面提供“再次挑战”和“返回主界面”。每次挑战重新生成种子，不支持中途存档或继续未完成单局。上述内容是目标设计，尚未代表运行时已实现。

## 9. 已确定的视觉风格

背包与 HUD 统一采用现代二游风格：雾蓝灰面板、象牙白文字、香槟金选中态、精致物品卡片与柔和层次。配色、图标、面板及参考图统一见 [UI 美术规范](../../Assets/ui/README.md)。

## 10. 当前未确定内容

当前暂不规定：

- DOM 组件框架
- UI 编辑器化方案
- 输入焦点系统
- 动画系统
- 响应式布局细节
- 多目标交互焦点的具体实现（基本按键、迷雾、圈状态提示及只有 ESC 菜单暂停的规则已确定）

实现阶段可以根据需要提出方案。
