## 美术风格：现代二游风格

背包与 HUD 统一采用雾蓝灰、象牙白、香槟金配色，搭配精致物品卡片、柔和层次与克制留白。

视觉参考：[背包样图](concepts/2026-10-05-style-comparison/D-inventory.png)、[HUD 样图](concepts/2026-10-05-style-comparison/D-hud-v2.png)。

### 配色基准

统一使用以下色值，透明度与局部渐变按场景可读性调整。

| 用途 | 基准色 | 使用规则 |
| --- | --- | --- |
| 深层底色 | `#17212B` | 背包遮罩、深层容器，冷静且低饱和 |
| 面板／卡片 | `#293744` | 雾蓝灰，柔和透明层次；文字区域保证足够遮底 |
| 边框／分隔 | `#526574` | 低对比细边，避免密集网格和厚框 |
| 主文字／功能图标 | `#E8ECEF` | 象牙白，清晰但不刺眼 |
| 次要文字 | `#AAB6C1` | 与主文字拉开层级，不降低关键信息辨识度 |
| 选中／主要操作 | `#D7BF86` | 香槟金，局部细描边、浅渐变或轻微高光 |
| 辅助信息强调 | `#91CCD5` | 少量浅青，用于属性等重点，避免铺满面板 |
| HP | `#C99598` | 低饱和淡红色 |
| SP | `#AECBB2` | 淡绿色 |
| ST（耐力） | `#D8CF9F` | 淡黄色 |
| 毒／火／影 | `#98C96C` / `#E69A56` / `#A599CB` | 元素与状态的局部语义色；各有独立图形，不只依赖颜色 |

### 面板、图标与文字

- 面板使用薄边框、小圆角（1080p 下约 6px）、柔和明暗渐变与适量留白；装饰只允许少量简洁几何细节。选中态以香槟金边框和局部高光表达，悬停弱于选中，禁用降低饱和度但保持可辨。
- 物品、武器和装备图标采用精致的简化写实插画，轮廓鲜明、材质适度概括，统一左上方柔光与视觉比例。武器／装备依实际模型制作；同类物品统一视角。透明图标与卡片底框分离，选中框、数量和品质提示由 UI 叠加。
- 模型只提供装备的大体形状、识别特征与配色参考，不限制图标的细节程度。图标应补足自然曲面、布料裁片、缝线、扣具、材质与结构层次，不能照搬模型制作能力造成的方块轮廓、简化袋体或鞋底几何。
- 图标不刻意追求绝对真实或照片级微纹理；以精致、适度概括的游戏插画表现为准，优先确保形状美感、材质层次与小尺寸识别度。
- 材料稀有度通过主体表现区分：异变结晶按制作人最终选择使用初版紫灰单枚晶体，无外围特效；火魔晶核与恶毒晶核同等级且稀有，使用饱满多面晶簇，保持相近体量和精细程度，允许少量贴近主体的元素辉光、余烬或薄雾微粒，背景仍透明。
- HUD 功能图标采用统一粗细的简洁白色图形，状态图标用对应语义色；小尺寸优先清晰轮廓，避免把物品插画的全部细节缩进状态图标。以 24～32px 检查 HUD 图标识别度。
- 中文正文与功能标签使用清晰的无衬线字体；标题可通过字号、字重和间距建立层级。数字保持整齐对齐；不采用手写标语、仿旧模板字或复杂装饰字。
- HUD 保持中心视野通透，亮场景下用轻阴影或局部深色衬底保证可读；保留右上角小地图等既定功能位置，具体尺寸与响应式布局由 UI 实现确定。
- 不使用重做旧、锈蚀纹理、满屏霓虹、强烈外发光、厚重浮雕、卡通粗描边或繁复奇幻花纹。

### HUD 组件规范

- 武器槽：五个简单矩形卡片，浅色剪影与小号槽位按键；细边框、轻选中提示，不加复杂外框。右下武器信息显示弹药、名称与射击模式，使用无边框的深色渐隐背景。
- 消耗品槽：位于武器槽右侧，显示物品图标与右下角数量（如 `2`）；不显示名称或 `x` 前缀。下方保留 `Q 切换`、`T 使用`，背景采用无边框的轻渐隐处理。
- 属性条：左下竖排 HP、SP、ST，使用淡红／淡绿／淡黄填充；不显示具体数值。三个图标与标签统一象牙白 `#E8ECEF`，底部仅用轻渐隐背景，不做独立卡片。
- 状态与冷却：属性条上方排列小方形图标，包含毒伤、灼烧、翻滚与暗影双刃。毒伤、灼烧的层数叠在图标右下角；技能冷却不显示层数。不显示名称、秒数或通知条，使用低饱和图形与克制底色。
- 进度：以裁切在方形图标内的 360° 半透明深色扇形遮罩表示剩余比例，不用亮色外圈。毒伤取当前层毒素／每层容量（参考 100）；灼烧取剩余时长／当前层最大时长；技能取剩余冷却／本次总冷却。比例归零时遮罩消失。
- 层数与遮罩均由运行时叠加，不烘焙进图标资产。毒素恰为每层容量整数倍时，当前最高层为满层；状态结束时移除对应状态图标。

### 内容与参考范围

UI 文字仅包含名称、属性、操作与必要状态反馈，不添加装饰性标语或氛围文案。

样图仅作视觉参考；功能、数值、按键与槽位规则遵循 Design 和程序配置。

### 后续工作方式

制作前阅读本规范与两张参考图；同类图标保持光照、视角、轮廓与细节密度一致，优先参考已有验收图标。验收后登记到 UI 资产配置表。

## 分类与命名

- `icons/`：专门存放 UI 图标，按需建立 `status/`（状态）、`items/`（物品）、`equipment/`（装备）、`elements/`（元素）等子目录。
- 后续面板、按钮背景等非图标 UI 资产，在 `ui/` 下按用途另建子目录。
- 文件名使用小写英文与下划线，建议 `ui_<类别>_<名称>[_<状态>].<扩展名>`；例如 `ui_status_poison.png` 仅为命名示例，并非已有资产。

## 交付约定

1. 图标交付透明背景 PNG 或可内嵌 SVG；具体尺寸、格式、颜色及交互状态按对应工作项确定，并登记实际规格。
2. 保证小尺寸可辨识；毒伤、灼烧等状态不能仅靠颜色区分。层数、倒计时及阈值提示由 UI 动态显示，不烘焙进基础图标。
3. 不依赖远程图片、字体或图标库；SVG 不引用外部资源。运行时接入需保持离线自包含入口。
4. 每份交付登记到 [UI 资产配置表](../UI资产配置表.md)，填写实际路径、规格、用途和接入状态。设计依据见 [UI 设计](../../Design/UI/UI.md)。
