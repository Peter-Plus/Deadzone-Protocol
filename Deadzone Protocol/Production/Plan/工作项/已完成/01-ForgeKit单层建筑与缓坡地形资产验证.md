# 工作项 01：ForgeKit 单层建筑与缓坡地形资产验证

状态：已完成。创建日期：2026-10-05；完成归档日期：2026-10-05。已完成单层建筑、缓坡地形资产与空间契约验证，结果及已知限制见 [01-资产验证报告](../报告/01-资产验证报告.md)。下文保留原始执行要求，实际交付以报告为准。

## 1. 目标与背景

《死区协议》是单机 FPS 生化生存项目，目前可玩内容为第一人称训练场；正式世界、敌人导航、物资生成尚未完成。本轮先验证“荒漠中随机分布小聚落、可进入的单层建筑、舒缓起伏地形”是否适合作为后续世界设计基础。

制作人特别关心：即使只有一层楼，室内地坪也可能高于室外，敌人如何进入？本验证采用**抬高地坪＋连续入口缓坡**，玩家与敌人沿坡进入，不依赖跳跃、自动爬台阶或瞬移。建筑仍需明确尺寸和通行约束，不能把整栋建筑当实心碰撞盒。

你负责在 ForgeKit 工具链基础上完成地形、建筑生成和资产验证，提供后续运行时验证可直接消费的模型、数据、生成工具和预览。不是只写方案，也不是制作正式游戏地图。

后续工作：02 将使用本项产物制作随机建筑与敌人寻路验证；03 将进一步验证室内外彩色方块投放。本项不实现敌人 AI 或物品 Gameplay。

## 3. 验证内容和规模

采用以下可配置起始规模，允许根据实际运行成本小幅调整并解释：

- 约 160 × 160 米的连续地形，不得缩成只有一栋房子的展示台。
- 每个场景约 12～18 栋可进入建筑，形成至少三个疏密不同的小聚落，中间保留移动区域。
- 至少三种建筑模板：双出口单间、带内部隔墙和转折通路的小屋、开敞入口仓库。可以使用简单末世材质配色，不要求正式美术精度。
- 至少约三分之一建筑使用明显抬高的室内地坪，室外到室内高差建议 0.2～0.5 米，入口必须通过可见缓坡连接。
- 地形至少包含连续平地区、缓坡和浅洼/低丘，总高差建议 2～4 米。不得只改变颜色或用视觉地形覆盖实际平面碰撞来冒充起伏。
- 支持 seed，至少交付三个布局有明显区别的固定 seed 示例，并允许生成新 seed。随机影响地形变化及合法建筑位置/朝向；不能仅随机颜色。

本项只做核心地面与可进入建筑，不制作小石头、草、车辆等装饰物，也不以实心建筑填充数量。不做多层楼、可达屋顶、地下室、桥洞叠层、动态门、破坏、楼梯、攀爬或跳跃必经路线。

## 4. 建筑和地形资产约束

以下是验证约束，不是最终游戏永久规格。数值可在验证中收紧；不能通过静默缩小角色来满足净空。

| 项目 | 验证要求 |
| --- | --- |
| 单位与坐标 | 米制、+Y 向上、+Z 为建筑局部正前。建筑根原点位于地基底面中心，scale=1；地坪标高单独记录。 |
| 角色参考 | 玩家胶囊现为半径 0.3m、高 1.8m；A1 基础身高约 1.8m；B2 约 2.34m。高度不等于模型最大运动包围盒，需检查实际模型和动作余量。 |
| 门和主通道 | 起始净宽不少于 2.4m、门净高不少于 3.0m，室内净高建议不少于 3.2m；净尺寸扣除墙、门框、屋顶及斜坡影响后测量。至少双出口模板两端真正连通。 |
| 室内外高差 | 不要求处处同高；每个声明可通行入口必须有连续缓坡接到室内地坪。门槛不制作正向凸起台阶；几何接缝以连续齐平为目标，不依赖角色控制器跨越误差。 |
| 入口坡道 | 建议最大 12°，净宽不小于相连入口；长度由高差和坡度计算，坡顶/坡底平顺衔接，预留转向空间。坡道是可见且有碰撞的实际结构。 |
| 室外地形 | 声明可走区域建议最大坡度 15°；没有悬崖、深坑、悬空面或不可避免的垂直台阶。地形接缝不造成卡脚或坠落。 |
| 建筑落地 | 在坡地上选取或生成水平建造平台，建筑不随坡倾斜。平台及入口与外围地形连续连接；地形不得穿进室内，基础不得悬空。 |
| 墙和屋顶 | 具有合理厚度、正确朝向与室内可见面；不能只靠单面薄片制造漏光/穿透。屋顶不作为可走层。 |
| 碰撞 | 显式交付简化静态碰撞数据，分别描述墙、地板、屋顶、坡道；禁止用整栋外包盒堵住房间和门。 |
| 可通行性 | 入口、内部通路和室外连接都有数据；可走面与实际碰撞/视觉来自同一几何依据，不能三套独立手绘数据相互漂移。 |
| 放置范围 | 建筑预留占地含地基、坡道、入口净空及必要间距；旋转后仍检查。预留占地不等于不可通行区。 |
| 交付格式 | 建筑和地形模块 GLB 自包含，无外部贴图请求；场景实例与辅助数据 JSON。字段的坐标系、单位、旋转单位必须写清。 |

没有自动台阶能力不妨碍本方案：本项通过真实坡道跨越地坪高差。禁止把入口做成高台，要求后续 02 自行瞬移、跳跃或关闭碰撞进入。

## 5. 必交数据与可复用生成入口

交付 `handoff.json` 作为唯一交接入口，并附 `README.md` 解释。内部路径统一相对本项目录，包含 schemaVersion、生成器版本、seed 示例、资产清单、文件校验值、预览入口和实际生成命令。不要要求下一项猜 GLB 节点语义或从截图推测布局。

至少提供以下信息，具体字段名可自行合理组织并文档化：

1. **建筑模板**：稳定 templateId、视觉资产、地基/预留范围、地坪标高、墙与屋顶等碰撞体、可走面、门口及坡道连接、室内区域。
2. **生成场景**：seed、地形描述/资产、建筑 instanceId 和 templateId、完整实例变换、建造平台及入口连接。所有数据采用同一实例变换，不能只旋转模型。
3. **地形依据**：足以重建碰撞和查询实际地面高度/法线的数据，明确多斜面接缝与建筑地板的优先关系；不得只给视觉 GLB。
4. **物资候选区**：每种建筑至少一个明确落在室内的可采样区域，带 regionId、语义标签、局部范围/多边形及地坪高度依据；另有室外候选区。标注门口、坡道和主通路禁放范围。03 将在区域内随机采样，而非只使用单一固定坐标。
5. **再生成接口**：接受 seed 和规模配置，生成匹配的地形与建筑布局；02 可以在 Test 内直接运行/复用。地形建造平台与建筑布局须联合生成，不能随意移动已生成建筑后留下悬空基础。
6. **验证工具**：检查必填字段、引用路径、尺寸、重叠、坡度、入口连接和坐标变换。格式版本不兼容应明确报错。

不要交付只有固定整场 GLB 的结果。可以另导出整场 GLB 供查看，但独立建筑模板、实例清单和再生成能力必须保留。全局随机使用独立且可复现的种子流，避免后续添加物资后改变既有建筑布局。

## 6. 验证与证据

提供本项目录内可双击离线打开的 `Preview.html`，显示完整地形、随机建筑布局，并可检查室内。资源通过构建内嵌或明确的本地文件选择方式加载，不依赖联网、服务器或关闭浏览器安全设置。不要修改 ForgeKit 原预览器；可只读复用其工具和本地库。

至少完成：

- ForgeKit 定义校验、编译及 GLB 加载验证；单独生成的实验地形使用相应验证器，不能谎称通过不适用的 ForgeKit Schema。
- 三个固定 seed 的可复现比较；至少包含不同朝向、起伏地形和抬高地坪建筑。
- 每个模板的尺寸、净空、墙体/入口/坡道连续性检查；对至少一个抬高地坪入口提供标高、坡长、坡度的可视化证据。
- 全场建筑、坡道与预留范围无非法重叠；入口没有被其他建筑或地形封住。
- 利用玩家/A1 的体积参考，以及 B2 模型尺寸参考检查净空；可使用静态角色或胶囊量规，不要求本项实现角色导航。
- 截图涵盖全图、聚落、各类室内、坡地落脚和入口高差。不能只拍外观。

本项“通过”只证明资产、空间契约和静态检查成立；实际玩家移动、敌人进出与拥堵由 02 验证，报告中必须保留这个界限。能打开浏览器不等于无碰撞问题。
