## 1. 目标与现状

在独立验证场景中加载已有玩家、敌人模型和动画，使用前序 ForgeKit 生成的单层建筑与缓坡地形，随机分布建筑和敌人，验证玩家移动、敌人室内外寻路、地坪高差及多人通行。

关键问题：室内地坪可以高于室外，通过可见、有碰撞的缓坡连接。玩家和敌人必须实际走入，不允许瞬移、穿墙、自动抬升或强制贴到目标点来伪装成功。

## 5. 导航、运动与资产衔接

具体使用网格寻路或导航网格由你根据实物决定，不要求制作人先指定算法。无论采用何种算法，必须满足：

1. **生成预留、导航、碰撞各司其职**：建筑预留范围防止放置重叠，不能整块标为墙；室内与入口保持可达。导航考虑角色半径、高度、坡度、边界和转弯余量，不能只检测一个点能否通过。
2. **真实地形运动**：坡面、地板和入口使用与视觉对应的碰撞；玩家和敌人靠控制器或等价可靠碰撞移动，最终脚底高度来自实际支持面。不能把模型贴地但碰撞仍在原平面。
3. **高差通行**：沿 01 缓坡上下室内地坪；验收路径不依赖跳跃和自动爬台阶。入口目标坡度不超过约 12°、室外可走坡面不超过约 15°，实际数值以交接数据为准，并与运动控制器一致。
4. **基本行为**：闲置/巡逻、追击、抵达目标或稳定停靠；允许一个明确的测试按钮让敌人追踪玩家。不需要完整感知和技能系统，但不能把所有角色直接朝玩家直线推过去。
5. **重新规划与拥堵**：玩家移动后可以更新路线；多敌人通过门口时合理排队、绕行或等待，不无限堆叠、不穿墙。使用实际位移判断卡住，记录持续时间与原因，避免每帧全体重新搜索。不得用隐形扩大门口碰撞间隙掩盖拥堵。
6. **不可达目标**：报告不可达或在合法位置等待；不得穿墙/瞬移。导航平滑后的线段也须可通行，不能切过墙角。
7. **墙体遮挡**：不能隔墙判定抵达或近身接触；若加入攻击，必须有距离与遮挡检查。可用接触范围调试标记替代完整伤害。
8. **大体型**：至少验证 B2 的实际体积通过被声明支持的入口；遇到不支持的通道应明确判不可达，不偷偷缩放。动画运动包围范围与胶囊的差异须报告。

当前玩家 Rapier 接入设置过爬坡角度和地面吸附，但坡面未正式验收，也没有敌人导航。需要在本项检查和调试，不能引用已有设置就认定通过。

## 6. 调试能力与验收矩阵

页面显示 seed、敌人数、帧时间、导航搜索/更新时间与卡住计数；至少可切换导航/路径、碰撞、入口与坡道、角色体积等调试视图。提供暂停、重置、切换 seed，以及单敌人/群体追击方式。视图不能替代真实运动判定。

至少完成以下有记录的案例：

| 案例 | 必须看到的结果 |
| --- | --- |
| 室外绕建筑进入室内 | 敌人绕墙找到真实入口，进入后到达玩家附近。 |
| 室内追到室外 | 通过门口离开，不撞墙原地持续跑步。 |
| 双出口建筑与转角室内 | 能选择连通出口并绕过隔墙，路线平滑不穿角。 |
| 抬高地坪入口 | 玩家与 A1、B2 在不跳跃条件下完成上坡进门、下坡出门。 |
| 地形连续坡面与接缝 | 双向通行，不明显下沉、悬空、卡脚或抖动。 |
| 至少 10 个敌人同时通过宽入口 | 可以逐步通过；报告排队与最长停滞，无持续死锁和穿墙。 |
| 目标被静态结构隔断/在不可达位置 | 明确不可达或合法等待，不借助瞬移解决。 |
| 初始室内随机出生 | 不在墙内、屋顶、地板下面，能离开所在房间。 |
| 重置与换 seed | 旧物理、角色和动画正确释放，无重复实例或持续增长。 |

至少对 20 个固定 seed 做生成合法性及导航连通性检查，对其中三个有代表性的 seed 完成实际浏览器运动检查。默认 30 敌人和压力档 50 敌人分别记录运行环境、分辨率、持续时间和平均/P95 帧时间；建议每档持续约两分钟，包含室内外追击。没有测试就不声称达到正式项目 90/120 FPS 目标。

自动检查至少覆盖随机复现、非法出生、角色净空、路径连通和不可达情况；运行时检查覆盖实际碰撞与门口通行。若自动化环境不能验证 file:// 或鼠标锁定，记录已验证路径与尚需人工操作，不用 HTTP 结果冒充双击入口验收。
