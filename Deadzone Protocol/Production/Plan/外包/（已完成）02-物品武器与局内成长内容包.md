# 外包工作项 02：物品、武器与局内成长内容包

> 状态：已根据制作人回复整合进正式 Design。本文保留为历史委托说明，其中“不修改正式 Design”等交付约束不适用于当前已完成的整合工作。当前事实来源是 `Design/Item/Item.md`、`Design/Item/ItemContent.md`、`Design/Combat/Elements.md` 及其关联文档；制作人原始回复在 `Production/Plan/外包/制作人回复/制作人关于物品和局内成长设计的回复.md`。

## 面向策划（制作人）的工作项简介

为《死区协议》设计玩家在一局中能够发现、携带、使用、取舍和购买的首批内容，建立从弱小开局到迎战 Final 的局内成长体验。

本项关注“玩家搜什么、为什么换、怎样形成不同构筑”，不负责规定 Inventory、Equipment、Weapon 或 UI 的程序实现细节。成果是供制作人选择的内容提案，不直接写入正式 Design。

## 一、工作目标

提交一套完整但规模可控的首批物品与局内成长方案，至少回答：

- 搜索物资为什么值得冒险，而不是只捡数值更高的同类物品？
- 武器、弹药、治疗、SP、Stamina、背包和特殊物品如何形成有意义的容量取舍？
- 玩家在一局内能形成哪些不同但可理解的成长方向？
- 普通商人与军火商分别提供什么价值？
- 哪些内容属于首版闭环，哪些应留给后续扩展？

## 二、工作内容与范围

### 1. 局内成长总体结构

- 描述玩家从出生装备不足，到逐渐建立生存能力，再准备 Final 的成长过程。
- 说明成长主要来自哪些选择：武器更换、物资储备、背包升级、消耗品组合、风险区域探索、商人交易或其他合适方式。
- 说明如何避免成长退化为单线性的“稀有度越高、所有数值越高”。
- 说明背包容量如何在内容层面制造真实取舍，但不设计其程序规则。

### 2. 首批内容目录

规划规模适中的首批内容，可包括：

- 枪械；
- 近战武器；
- 投掷物；
- 弹药与必要的弹药差异；
- HP 治疗与应急物品；
- SP 恢复效率或环境适应类药品；
- Stamina 或行动辅助物品；
- 背包升级；
- 军备、防护或战术工具；
- 少量特殊物品或事件物品。

可以调整类别，但需说明原因。每项内容至少描述：

- 名称与一句话用途；
- 对玩家决策的价值；
- 适合出现的阶段和地点；
- 稀有程度或获取难度；
- 与其他内容的组合或冲突；
- 是否需要新资产；
- 是否适合首版。

优先复用现有武器资产，但不要因为已有模型就强行让九件武器全部进入首版。

### 3. 武器阵容与角色差异

- 从现有和可扩展武器中，选择一套有清晰定位的首版阵容。
- 说明每把武器为玩家提供的战斗选择，而不是只列射速、伤害和弹匣大小。
- 说明不同武器在近距离、远距离、弹药压力、机动性或敌人应对方面的价值。
- 必要时提出后续武器方向，但不展开配件、耐久、高级弹道或复杂品质词条。

### 4. 构筑与选择路线

设计若干局内成长路线，例如但不限于：

- 稳定生存；
- 火力压制；
- 机动探索；
- 精准节省弹药；
- 高风险高收益。

不必采用这些名称。每条路线应说明：

- 它依赖哪些类型的内容；
- 它擅长解决什么问题；
- 它付出什么代价；
- 它在 Final 前如何逐步成形；
- 玩家临时改变路线是否可行。

路线不应变成固定职业或永久天赋系统，除非将其明确列为另一个长期提案。

### 5. 商人与获取渠道

- 设计普通商人和军火商的内容定位与差异。
- 说明地图搜索、危险区域、敌人、空投、商人和事件分别适合提供什么类别的物品。
- 可以提出简洁的交易资源概念，但不展开完整经济模型和价格公式。

### 6. 制作范围分级

将全部内容分为：

- **首版核心**；
- **首版可选**；
- **后续扩展**。

分级需考虑玩法价值、内容重复度、资产成本和实现复杂度，但不替开发者设计数据结构或系统接口。

## 四、必交成果

请返回以下 3 个 Markdown 文件的完整内容：

```text
物品武器与局内成长设计提案.md
首批物品与武器目录.md
首版物品内容优先级.md
```

### `物品武器与局内成长设计提案.md`

应包含：

- 局内成长体验目标；
- 内容分类与相互关系；
- 武器阵容思路；
- 容量取舍与搜集动机；
- 构筑路线；
- 商人与其他获取渠道；
- 主要风险、替代方向和制作人需要选择的问题。

### `首批物品与武器目录.md`

使用便于筛选的表格汇总：

- 名称；
- 类别；
- 核心用途；
- 获取阶段或渠道；
- 稀有程度；
- 主要取舍；
- 关联内容；
- 资产需求；
- 建议优先级。

可使用相对等级或体验描述，不要求最终平衡数值。

### `首版物品内容优先级.md`

应给出：

- 首版核心、首版可选、后续扩展三档清单；
- 推荐的内容制作顺序；
- 对现有九件武器资产的使用建议；
- 每一项保留、合并或裁剪的理由；
- 能够先用简单图标、几何体或现有模型验证的内容。

## 五、约束与工作原则

- 项目文档是当前事实来源；文档没有规定的内容可以大胆提出，但必须保持“提案”身份。
- 不直接改写或声称已经更新 `Design/`。
- 不虚构当前已经实现的背包、拾取、商店、属性或武器功能。
- 不负责 ItemInstance、Inventory、Equipment、Combat、UI 的接口、对象关系、状态边界或代码文件。
- 不进行最终精确平衡；必要时使用相对强弱、稀有度、体验目标或示例区间。
- 不用大量低差异物品填充目录；每个首版内容都应提供明确选择价值。
- 物品设计必须服务单局生存、搜索、容量取舍和 Final 准备，而不是脱离核心循环建立庞大的收集系统。
- 若提出新资源、货币或品质体系，应说明它解决的问题，并优先给出更简单的替代方案。
- 如果存在多个方向，比较后给出明确推荐。
- 使用中文编写，术语可以保留必要英文。

## 六、不在本工作项范围内

- 编写或修改任何代码；
- 规定物品系统的数据结构和操作边界；
- 设计背包 UI 的具体 DOM 结构；
- 完整商店经济、掉落算法或价格公式；
- 枪械配件、耐久、多弹种库存和复杂品质词条的详细设计；
- 制作模型、图标、动画、声音或特效；
- 修改正式 Design 或宣称提案已经获制作人批准。

## 七、完成标准

成果应达到：制作人能够据此选择首版物品规模、武器阵容和局内成长方向；后续 Codex 可以独立将被采用的内容转化为正式规则、配置和开发计划。
