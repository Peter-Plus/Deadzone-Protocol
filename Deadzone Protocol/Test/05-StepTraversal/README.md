# 低门槛与敌人寻路可行性验证

2026-10-06。隔离验证，未修改游戏 src、Play.html、旧 Test 或 ForgeKit 建筑样件。测试使用项目现有 Rapier 0.21.0；模型以玩家/A1/B2 胶囊量规表示，没有新增敌人正式 AI。

## 运行

在游戏根目录运行：

```powershell
node Test/05-StepTraversal/stability.mjs
```

稳定性检查包含 307 个单体案例，以及平地/10cm 门槛两组各 10 个混合体型角色的队列案例。未全部通过时退出码为 1。结果写入 `evidence/stability-10cm.json`。

`run.mjs` 保留最初 5～20cm 探索矩阵；20cm 原生自动跨步存在失败，这个探索命令预期可能退出 1，不把它当作应全绿的回归套件。第一轮原始结果保存在 `evidence/first-pass-20cm.json`。`evidence/unguarded-crowd.json` 保留未加入前方角色等待规则时的群体失败，不能删除后宣称原生群体移动天然稳定。

## 方法

- `traversal.mjs`：同源盒体场景、A* 和 Rapier 角色控制器。角色只通过 `computeColliderMovement` 移动，没有传送到目标、手工抬高脚底或隐藏坡道。
- 玩家量规半径 0.3m/高 1.8m，A1 0.78m/1.95m，B2 1.34m/3.2m，沿用 Test/02 保守体型；不是对最新动画外包络重新测量。
- 物理胶囊自动跨步开启；物理探测高度 0.22m、最小探测落脚宽度 0.25m、向下贴地 0.24m、碰撞间隙 0.008m、坡度 15°。这些是测试参数，不是美术允许的台阶高度：测试表明只按探测值承诺 20cm 不可靠。
- 稳定方案的导航允许向上 0.10m、向下 0.20m。A* 仍是 0.5m 网格，边按 0.05m 采样做空间检查；方向敏感，不把上行和下行共用一个无向可达缓存。
- 玩家物理移动不受“整个脚底必须处于同一高度面”限制，实际重力处理离边下落。AI 仍先检查路线净空和高度合法性。
- 单体通过标准：25 秒内到达，最大连续水平停滞不超过 0.25 秒，脚底不得穿到基准地面下 0.08m。拒绝案例分别验证导航拒绝和实体阻挡。
- 群体使用实际角色之间的碰撞；接近前方角色时先停止前进，避免接触后被挤到门边。保留通行队列，不允许穿过其他角色或把等待者传送进屋。

## 范围

覆盖 5/10cm 高差、三种体型、30/60/120Hz、多个摆放角度、正面/30°/60° 接近；另有绕墙进屋、斜向进门、双出口贯通、离开房间、从 20cm 平台侧面下落、低净空、过窄门洞、过高地坪拒绝、三段宽台阶及 40 个固定种子敌人进屋案例。

门洞基准净宽 3.6m，适配保守 B2；连续台阶每段深 3m。结果不能外推为所有狭窄楼梯、碎石堆、破损边缘均可通行。

群体案例是单向有序通过、分散的最终停靠点；没有验证双向对冲、玩家堵门、混合攻击动作和完整地图规模。平地对照只保留 1mm 地板避免零厚度碰撞，其余结构和队列相同。

详细结论见 [可行性报告](../../Production/Reviews/StepTraversalFeasibility.md)。
